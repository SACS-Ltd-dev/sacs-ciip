Why an investigator needs to understand networks

Last week you met the four roles and the intelligence cycle. This week you learn the plumbing underneath all of it, because every single lead you will ever chase, an email, a phone, a website, a bank transfer, travels across the same basic infrastructure you are about to learn to read.

Here is a fact that surprises most beginners. You do not need to be a network engineer to investigate cybercrime well. You need something narrower and more practical: you need to be able to look at an IP address, a domain name, or a piece of network traffic and immediately understand what it is telling you, and just as importantly, what it is not telling you.

That second half matters more than people expect. A huge number of wrongful accusations in this field come from someone treating an IP address as proof of identity, when in reality an IP address is closer to a partial car number plate glimpsed in the rain. It narrows things down. It does not name a suspect on its own. You will see exactly why later in this resource.

What you will walk away with today. A working mental model of how IP addresses, DNS, and ports fit together, hands on practice reading a real style WHOIS record for red flags, comfort typing real Linux commands in a safe simulated terminal, and a clear plan for building the virtual machine you will use for the rest of the program.

The story that runs through this whole resource

In Week 1 you read about the phishing email built in the style of the real Unatrac case, sent from the lookalike domain untarac-holdings.com. We are going to keep following that exact domain today. You will use WHOIS and DNS tools to investigate it the way a real analyst would, then use the Linux terminal to run some of the same lookups yourself. By the end of this resource, a domain name will not look like a random string of letters to you anymore. It will look like a set of clues.

The building blocks

IP addresses, DNS, and ports

Three ideas carry almost all of the networking knowledge you need for this field. Click through each one below.

1. IP addresses: the internet's postal address system

Every device connected to the internet needs an address so that data knows where to go, in the same way a letter needs a house address. That address is called an IP address. Click each part of the address below to see what it actually tells an investigator.

Click one of the number blocks above to see what that part of an IPv4 address can tell an investigator.

This particular style of address, four numbers separated by dots, each between 0 and 255, is called IPv4, and it is still the most common format you will encounter. A newer, much longer format called IPv6 also exists and is becoming more common, but the reading skills are the same.

The single most important lesson in this whole section. Because of a technology called NAT, short for Network Address Translation, one public IP address can represent dozens, hundreds, or with mobile networks sometimes thousands of different people at once. A Nigerian mobile network provider might route enormous numbers of customers through a small handful of public IP addresses using a technique called CGNAT. This is exactly why an IP address alone is treated as a lead, never as proof. Real attribution needs a subpoena to the internet provider asking who held that specific IP at that specific second, matched against their internal logs.
Address rangeWhat it means
10.0.0.0 to 10.255.255.255A private range. Used inside a home or office network, never visible directly from the public internet.
192.168.0.0 to 192.168.255.255Also private. The range you have almost certainly seen on your own home router's settings page.
Everything elseGenerally public and routable, meaning it can be reached from anywhere on the internet, and can usually be traced to a specific internet provider and rough geographic region.

2. DNS: the phonebook that hides behind every website name

Nobody wants to type a string of numbers to visit a website, so the Domain Name System, DNS, exists to translate a human friendly name like a company's website into the IP address a computer actually needs. Click through the six steps below to see what really happens the moment you type a web address and press enter.

STEP 1

You type it

You type unatrac.com into your browser and press enter. Your computer has no idea what IP address that is yet.
STEP 2

Resolver asked

Your computer asks a DNS resolver, usually run by your internet provider or a service like Google's 8.8.8.8, to find the answer.
STEP 3

Root server

The resolver asks a root server which organisation manages the ".com" part of the internet.
STEP 4

TLD server

That ".com" server points the resolver to the specific nameservers responsible for unatrac.com itself.
STEP 5

Authoritative answer

Those nameservers give the final, authoritative answer: unatrac.com currently lives at a specific IP address.
STEP 6

Page loads

Your browser connects directly to that IP address and the website loads. This entire chain usually takes a fraction of a second.

For an investigator, the useful part is that every one of those steps leaves a record somewhere, and DNS itself holds several different types of information beyond just the IP address, called record types. The ones you will use constantly:

Record typeWhat it holdsWhy an investigator cares
AThe IPv4 address a domain points toTells you where the site is actually hosted, sometimes revealing a hosting provider known for tolerating abuse
MXWhich servers handle email for the domainA domain built purely for a phishing email often has suspicious or freshly configured MX records
NSThe domain's nameserversFraud rings often reuse the same nameserver provider across dozens of scam domains, a pattern that links cases together
TXTFree text, often used for verification and anti spoofing recordsA missing or misconfigured SPF/DMARC record is another common sign of a hastily built scam domain

3. Ports and protocols: which door, and which language

If an IP address is a building's street address, a port number is the specific door on that building a piece of software knocks on. Different services agree in advance to use specific doors, so computers do not have to guess. Try matching the ports below to what they are typically used for.

Why HTTPS is not proof of legitimacy. Many beginners are taught to "check for the padlock" as a safety rule. It is not enough anymore. Free, automatic HTTPS certificates are available to literally anyone, including scammers. A lookalike domain like untarac-holdings.com can have a perfectly valid padlock. The padlock only proves the connection is encrypted, not that the website is honest.
Turning a domain name into evidence

Reading a WHOIS record like an investigator

WHOIS is a public lookup service that shows registration details for a domain name. It is one of the fastest, completely free ways to start building a picture of who is behind a website. Let us investigate that lookalike domain from the Unatrac style case.

Domain Name: UNTARAC-HOLDINGS.COM
Notice this is one letter off from the real company name, "Unatrac." This single letter swap is the entire trick. At a glance, in a busy inbox, most people read what they expect to see, not what is actually there.
Registrar: NameSilo, LLC
Registrant Organization: REDACTED FOR PRIVACY
Privacy protection services are common and completely legal, even for honest domain owners, so this alone is not proof of guilt. But combined with the other flags here, it removes one of the easiest ways to identify the true owner directly through WHOIS, meaning you will need to go further, for example checking payment trails or hosting provider records through a proper legal request.
Registrant Country: Unknown (privacy protected)
Creation Date: 2018-04-09
The real phishing email in the style of this case went out in April 2018. A domain registered just days or weeks before it was used is one of the strongest indicators in this entire field. Legitimate businesses rarely build a new domain days before sending an urgent payment change notice. Always check the creation date first.
Registry Expiry Date: 2019-04-09
Name Server: NS1.BULLETPROOF-DNS.NET
Name Server: NS2.BULLETPROOF-DNS.NET
Fraud infrastructure is frequently reused across many scam domains at once. If you look up this same nameserver provider in a real investigation using a free tool like a reverse NS lookup, you would often find dozens of other suspicious domains sitting on the exact same infrastructure. That is how single cases turn into networks of cases.
Domain Status: clientTransferProhibited
This is a completely normal, routine security setting on most domains and is not a red flag by itself. It is included here to teach an important investigative discipline: not everything unusual sounding in a technical record is actually suspicious. Learning to tell real signal from noise is half the skill.
Flags reviewed: 0 / 5
Free tools you can use for this today. The whois command on Linux and macOS, ICANN's free Lookup tool at lookup.icann.org, viewdns.info for historical WHOIS and reverse lookups, and crt.sh for certificate transparency logs that can reveal every subdomain a certificate was ever issued for. None of these cost anything, and all of them are legal to use on any public domain.

The Wayback Machine: seeing a website's past

One more free tool deserves its own mention. The Internet Archive's Wayback Machine, at web.archive.org, has been quietly photographing the public internet since 1996. If a scam website is taken down the moment its owners suspect they are being investigated, the Wayback Machine may still hold a saved copy of exactly what it looked like, when it first appeared, and how it changed over time. This has cracked open more than one case where the live evidence had already vanished.

A real world scale reminder. In August 2019, United States federal prosecutors unsealed a 252 count indictment against 80 defendants, most of them Nigerian nationals, accused of running business email compromise and romance scam operations across multiple countries. Two of the accused, Valentine Iro and Chukwudi Christogunus Igbokwe, were accused of laundering at least 6 million dollars through a Los Angeles based network, out of an estimated 40 million dollars taken from victims worldwide. The FBI investigation behind that case had begun all the way back in 2016. Cases like this are rarely cracked by one dramatic discovery. They are built, patiently, from exactly the kind of small technical details you just practised reading above.
Getting comfortable with the command line

Your own isolated environment

Setting up your virtual machine

Before you touch a live investigation, you need a computer inside your computer, one you can experiment on, break, and reset without any risk to your actual laptop or your personal files. This is called a virtual machine, or VM.

Why investigators insist on this, always

A virtual machine is a complete, isolated computer that runs as software inside your real one. If something goes wrong inside it, a suspicious file behaves unexpectedly, a dark web page tries something unusual, a tool you are learning crashes everything, you simply delete the VM or roll it back to an earlier saved state, called a snapshot, and nothing on your real machine was ever touched. This single habit will save you more than once over the course of this program.

1

Install VirtualBox

Download Oracle VirtualBox, completely free, from virtualbox.org. It runs on Windows, macOS, and Linux. This is the software that will host your virtual machine.

2

Download the Kali Linux VM image

Kali Linux is a free, purpose built Linux distribution used throughout digital forensics and security work. Go to kali.org/get-kali and choose the prebuilt VirtualBox image rather than the manual installer. This saves you an entire setup process.

3

Import the image into VirtualBox

Open VirtualBox, choose File, then Import Appliance, and select the Kali file you downloaded. Give it at least 4GB of memory and 40GB of disk space if your machine can spare it.

4

Start the machine and log in

Kali's default username and password are both "kali" on the current official images. Change this password immediately once you are in, using the passwd command you now know from Tab 4.

5

Take your first snapshot

In VirtualBox, right click your VM and choose Snapshot, then Take Snapshot. Do this now, while everything is clean. This becomes your safe restore point for the rest of the program.

Minimum machine requirements. You will want at least 8GB of RAM on your host laptop, ideally 16GB, and roughly 60GB of free disk space once you account for both VirtualBox and the Kali image. If your machine is older or lower spec, tell your mentor now rather than in Week 5. There are lighter weight alternatives available.

Week 2 glossary

IPv4 +
The most common addressing format on the internet, four numbers from 0 to 255 separated by dots.
NAT / CGNAT +
Technology that lets many devices, sometimes many customers, share one public IP address.
DNS +
The system that translates human friendly domain names into the IP addresses computers actually use.
WHOIS +
A free public lookup showing a domain's registration details, registrar, dates, and nameservers.
Port +
A numbered channel a specific service uses to communicate, like a designated door on a building.
VM / Snapshot +
A virtual machine is an isolated computer running as software. A snapshot is a saved, restorable state of that machine.
